# 架构文档组织方式

## 设计原则

- **按关注点分层**：合约层 / 前端层 / 集成层 / 运维层，四层分离
- **一个文档一个主题**：每篇只讲一件事，避免大杂烩
- **与代码目录对齐**：文档路径对应代码模块，易于定位
- **只记必要内容**：决策及原因、关键约束、模块边界，不记显而易见的东西

## 文档结构

```
docs/
├── prd/                          # 已有：需求文档
└── architecture/                 # 本目录
    ├── 架构文档组织方式.md         # 本文件：说明文档如何组织
    ├── overview.md                # 系统全貌：模块关系图 + 技术选型 + 数据流
    ├── contracts/                 # 合约层
    │   ├── design.md              # 合约设计：继承关系、权限模型、安全考量
    │   └── nft-market-permit.md   # 复杂合约专项：Permit 签名流程与链下验证
    ├── frontend/                  # 前端层
    │   ├── dual-sdk.md            # viem vs wagmi 双套前端的架构决策与对比
    │   └── state-flow.md          # 钱包连接 → 合约调用 → UI 状态刷新的数据流
    ├── integration/               # 集成层
    │   └── contract-frontend.md   # ABI 管理、地址配置、多链部署的集成约定
    └── deployment/                # 运维层
        └── runbook.md             # 部署和运行：合约部署、前端启动、环境配置、多链切换
```

## 各文档职责

| 文档 | 解决的问题 | 核心内容 |
|------|-----------|---------|
| `overview.md` | 新人/回顾时快速理解系统 | 模块关系图、技术栈、链上链下交互全景 |
| `contracts/design.md` | 合约间如何协作 | 继承/组合关系、访问控制、状态变更入口 |
| `contracts/nft-market-permit.md` | Permit 机制细节 | EIP-712 签名流程、链下构造与链上验证、前端集成要点 |
| `frontend/dual-sdk.md` | 为什么两套前端、差异在哪 | 选型原因、功能对齐关系、差异点清单 |
| `frontend/state-flow.md` | 链上操作如何驱动 UI | 钱包连接 → 授权 → 交易 → 事件监听 → 状态更新 |
| `integration/contract-frontend.md` | 前后端如何对接 | ABI 同步、合约地址配置、多链网络切换约定 |
| `deployment/runbook.md` | 怎样部署和运行系统 | 合约部署流程、前端构建与启动、环境变量配置、多链切换操作 |

## 编写约定

1. **决策优先**：先写"为什么这样设计"，再写"具体怎么做"
2. **代码可追溯**：涉及具体实现时标注文件路径，如 `viem-front/src/hooks/tokenbank/useDepositBalance.ts`
3. **图优于表，表优于文**：关系用 Mermaid 图，对比用表格，仅叙述用段落
4. **变更同步**：代码架构变动时，同步更新对应文档；文档过时即删除，不留僵尸文档
